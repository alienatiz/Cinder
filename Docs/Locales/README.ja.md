# Cinder

[English](../../README.md) · [한국어](README.ko.md) · **日本語**

**オーディオのバーンインを、もっと手軽に。**

Cinderは、イヤホンとヘッドホンのためのオーディオバーンインアプリです。
ピンクノイズ、音楽、周波数スイープから信号を選び、自分に合ったバーンインを
始めましょう。再生時間と休憩間隔を設定し、メニューバーで進行状況を確認。
これまでのバーンイン記録も一か所で管理できます。

現在のバージョンは **1.0.0-dev**、対象環境は **macOS 27 · Apple Silicon** です。
初の正式リリースに向けた開発版です。機能と変更内容は
[リリースノート（英語）](../../RELEASE-NOTES.md)をご覧ください。

## はじめに

1. ローカルでビルドした `Cinder (Dev).app` を開きます。手順は下の **ローカルビルド** を参照してください。
2. クイック再生で、イヤホンやヘッドホンを接続した出力デバイスを選びます。
3. 信号と実行プランを選びます。フルサイクルには60分以上が必要です。分割実行では、1回の時間と休憩間隔を指定します。
4. 音楽を使う場合は、「音楽」タブで内蔵曲を選ぶか、Macの音楽ファイルを追加します。
5. イヤホンを耳から外し、システムやDACの音量を低く設定します。出力先とアプリのゲインを確認してから開始してください。

再生中はメインウインドウやメニューバーから一時停止・再開・停止できます。
内蔵信号と音楽の再生に、アカウントやインターネット接続は必要ありません。

## 主な機能

- **クイック再生** — 40時間の連続実行、40時間の分割実行、時間の直接指定に対応。1回の時間と休憩を調整し、ノイズ・音楽・スイープや休憩を含む60分のフルサイクルを再生します。開始・一時停止・再開・停止を一画面で操作できます。
- **クイック再生 簡易モード** — メニューバーで出力先と再生時間を選択。ウインドウを閉じても再生や予約を維持し、状態・残り時間・予約を確認できます。
- **音楽** — ローカル音楽ファイルの選択と並べ替え、ファイル情報と初期読み取りの確認、7種類の内蔵曲のリピート再生に対応します。
- **出力** — 選択したデバイスの接続方式・メーカー・現在のサンプルレート・出力チャンネル数を確認できます。詳細で対応サンプルレートを表示し、リアルタイムメーター・細かなゲイン調整・ゲインプリセットを利用できます。Mac情報と公開参考仕様は別に表示します。
- **予約** — 1回限り・繰り返しの予約と、再生・予約プリセットのJSON/YAML読み込み・書き出しに対応します。
- **設定** — 英語・韓国語・日本語、システム・ライト・ダーク・カスタムテーマ、バー型・針型のPeak/RMSメーター、Dev・Stable更新チャンネルの選択に対応します。
- **実行履歴（設定）** — 直近500件の実行時間・休憩・ゲイン・完了や中断の結果をこのMacに保存し、検索・要約のコピー・書き出しができます。

アプリの初期ゲインは−30 dB、手動調整の範囲は−60〜0 dBです。
デバイスや参考プロファイルを選んでもゲインは自動で変わりません。
デジタルゲインとメーターは実際の音圧を示しません。アプリを開いたり
プリセットを読み込んだりするだけでは、再生や予約は開始されません。

## 実行プラン

| 選択 | 動作 |
|---|---|
| 40時間の連続実行 | 40時間を1回のセッションとして実行 |
| 40時間の分割実行 | 1回の時間と休憩間隔を指定。最後のセッションを残り時間に調整し、セッションの合計を40時間にする |
| 時間の直接指定 | 1分から1000時間まで、1分単位で1回のセッションを設定 |

たとえば1回3時間、休憩30分の場合、3時間のセッション13回と最後の1時間に
分かれます。13回の休憩を含む予定所要時間は46時間30分です。休憩が終わると
次のセッションが始まります。ウインドウを閉じても継続し、停止・アプリの終了・
出力先の変更や切断で残りのプランを取り消します。スリープなどで次の開始時刻を
1分以上過ぎた場合、自動では再開しません。

40時間は選択できるプランであり、すべての機器に推奨するバーンイン時間では
ありません。セッション時間にはフルサイクル内の休憩を含み、セッション間の
休憩は別途加算します。クイック再生ではセッション・信号・サイクル内の休憩・
セッション間の休憩を分けて表示します。完了予定は分割プラン全体が対象で、
準備や一時停止により遅くなります。フルサイクルを選んだ場合、最後を含む
各セッションに60分以上が必要です。

メニューバーの **クイック再生 簡易モード** では1・2・4・8・40時間、または直接入力を
選べます。1・2・4・8時間と直接入力は1回のセッションです。40時間の連続実行や
既存の分割プランも選べます。ポップアップを開くだけでプランは変わりません。
1回の時間・休憩・信号・音楽・ゲインの詳細はメインウインドウで設定し、簡易モードにも
同じ値を反映します。実行中や予約待機中はデバイスと時間の変更をロックします。

閉じるボタンや⌘Wで閉じるのはウインドウだけです。**Cinderを終了、または⌘Q**
で再生を終了し、残りの予約とプランを取り消します。メニューバーの
**Cinderを開く** からセッションに戻れます。アプリを再起動しても再生や予約を
自動では復元しません。アイコンは通常のメニューバー項目として表示し、位置や
優先度を強制せず、macOSとユーザーの配置に従います。移動するには⌘を押しながら
アイコンをドラッグしてください。[Appleのメニューバーガイド](https://support.apple.com/guide/mac-help/whats-in-the-menu-bar-mchlp1446/mac)も参照できます。

## 開発状況

実行履歴は再生中の約5秒ごとと状態変更時に保存します。予期しない終了後は
最後の保存時点まで記録を復元し、再生や予約を自動では開始しません。
記録された信号時間はアプリの再生区間であり、イヤホン出力の測定値ではありません。
集計対象は保持している直近500件です。音楽ファイルのパスやデバイスUIDは
記録や要約に含めません。

Macでの自動ビルドとオーディオ信号の検査は通過しています。実機でのノイズの
連続性、7曲の編曲と強弱、長時間再生、配布に関する検証は進行中です。
[検証状況（英語）](../../VALIDATION.md)と[1.0.0計画（英語）](../../ROADMAP.md)をご覧ください。

## ローカルビルド

macOS 27.0以降、Apple Silicon、Xcode 27.x、macOS 27 SDKが必要です。
標準ではSwift 6.4コンパイラをSwift 5言語モードと完全な並行処理診断で使用します。
Yams 6.2.2を固定依存関係とし、初回の準備にはインターネット接続が必要です。

```bash
bash Setup-Mac.command
bash Check-Xcode.command
bash Build-App.command
```

生成先は `dist/Cinder (Dev).app` です。ローカルのad-hoc署名を使用しており、
Developer ID署名・公証済みの配布版ではありません。パッケージ作成や
別途行うSwift 6検査は[ビルドガイド（英語）](../BUILDING.md)を参照してください。

公開バージョンは `1.0.0-dev` です。macOSバンドルの数値形式に合わせ、
マーケティングバージョンを `1.0.0`、内部ビルドを `5.0.0` としています。
アプリIDは `local.chu.cinder`、設定保存先は
`~/Library/Application Support/Swinder/` のまま、既存の設定を維持します。

## 画面と通知

完了・エラー通知は設定で任意に有効にできます。初めて有効にするときに
macOSの通知許可を求めます。完了・デバイス変更・失敗・実行できなかった予約を
音なしで通知し、一時停止や休憩のたびには通知しません。許可しなくても記録は残ります。

主な画面はクイック再生・音楽・出力・設定です。出力タブでデバイス・ゲイン・Mac情報を
確認できます。クイック再生の出力詳細ボタンもこのタブを開きます。予約はクイック再生、
実行履歴は設定、変更履歴とヘルプは設定のCinderについてから開けます。
長い音楽リストや変更履歴は検索またはページ切り替えで確認できます。

アプリの操作中は `⌘Return` で開始・一時停止・再開、`⌘.` で停止できます。
`⌘1`〜`⌘4` で画面を切り替え、`⌘,` で設定を開きます。予約待機中や準備中は
開始のショートカットも無効です。他のプレイヤーのグローバルなメディアキーを
横取りしません。

## 開発版と正式版

**設定 → 更新** でDev・Stable更新チャンネルを選択して保存できます。
インストール済みアプリのバージョンとチャンネルは別に表示します。選択だけでは
アプリや再生は変わりません。正式版はまだリリースされておらず、更新の
ダウンロードとインストールは未実装です。Swift言語モードと更新チャンネルは別の設定です。

| 区分 | 運用 |
|---|---|
| `dev` | 開発ソース。コミットとPull Requestではソース検査のみ実行 |
| staging | 変更がまとまった時点でActionsから手動でアプリをビルド・検証 |
| `main` | 初の正式リリースから、確認済みのソースを管理 |
| `v1.0.0` などのタグ | リリース用ビルド後、Releaseの下書きを作成 |

staging専用ブランチや常時稼働のビルドサーバーは設けません。開発アプリはActionsで
14日間保管し、同じ開発バージョンのビルドをコミットハッシュで区別します。
LTSは初の正式リリース後、保守の必要性に応じて判断します。
[リリースガイド（英語）](../RELEASING.md)を参照してください。
